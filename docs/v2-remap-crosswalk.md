# King's Edge V2: structural remap and preservation record

V2 is a proposed organisation of the same King's Edge mobilisation scope. Its stable internal IDs begin with `v2-`; the displayed numbers `2.1` to `2.6` describe the new hierarchy. The original V1 plan and its 106-file baseline remain intact. `src/data/v2/crosswalk.json` gives a machine-readable destination for every V1 project, programme deliverable, step, benefit and measure. The original V1 top-level plan is also retained verbatim at `src/data/v2/source-snapshot/kings-edge-plan.json`. The original detailed files remain in the V2 tree as unregistered source material.

This is a planning proposal. New cross-functional project owners are marked TBC; existing deliverable leads, decision histories and more mature delivery designs are retained. The V2 theory of change is labelled a working proposition rather than an institutionally approved theory.

## Preservation checks

`npm run validate:data` now runs `scripts/validate-v2-crosswalk.mjs` alongside both versions' existing validators. The crosswalk check covers all 16 original programme deliverables, 83 source steps, 47 benefits and six measures. It compares every original step output and every resource ask across the active destinations, confirms original detailed fields for the 14 unsplit deliverables, checks the integrated source narratives and decision histories for the two splits, and reconciles all five shared resources' annual FTE/cash profiles and allocations. The V1 checksum gate and the complete related-project inventory remain in place.

Legacy numeric IDs inside inherited explanatory prose and historical decision logs refer to V1. Current machine references, navigation, related project links and shared resource allocations use the stable V2 IDs. Display numbers are presentation labels and must not be used as database keys.
