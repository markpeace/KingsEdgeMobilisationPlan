# North Star

## Programme North Star

**Makes the King's graduate premium real, visible, navigable and evidenced for every student.**

This is the programme's communicable destination. It is intentionally concise enough to guide senior discussion and to provide a common test for the work developed underneath it.

## How the North Star relates to the theory of change

King's Edge should distinguish between three related but different layers:

**North Star -> Theory of Change -> Mobilisation Plan**

- **North Star:** the destination we can communicate and rally around.
- **Theory of Change:** the causal argument we need to be able to explain and test: why we believe the programme's interventions will produce the intended change.
- **Mobilisation Plan:** the projects, deliverables, sequencing, dependencies, resources and measures through which we act on that theory.

A useful shorthand is:

> **The North Star is the thing we sell. The theory of change is the thing we test. The mobilisation plan is the thing we manage.**

The theory of change is being developed as a programme-level causal model. It should not simply reproduce the four-project structure. The projects are useful programme-management containers, while the theory of change should explain the mechanisms and outcomes that connect work across them.

See `docs/08-theory-of-change.md` for the current working hypothesis.

## What we are producing

We are producing an interactive mobilisation site for the King's Edge programme.

The site should work as both a strategic map and a practical mobilisation tool. It should be clear enough for senior discussion, detailed enough to support delivery planning, and structured enough to evolve as the programme matures.

## Purpose of the site

The site will help users understand how King's Edge turns the graduate premium into a deliverable programme of work.

It will show how King's Edge connects:

- curriculum-embedded graduate value
- co-curricular opportunity and purpose
- extra-curricular belonging, navigation and student life
- evidence and articulation of the graduate premium

## Core hierarchy

The site should render the plan through this hierarchy:

**King's Edge -> Projects -> Deliverables -> Components -> Delivery steps**

At the top level, users should see four projects:

1. Curriculum Embedded Graduate Advantage
2. A Co-Curricular Scaffold for Purpose
3. An Extra-Curricular Invitation to Participate
4. Defining, Evidencing and Activating the King’s Graduate Premium

Each project contains four deliverables. Each deliverable contains a summary, owner, components, delivery steps, dependencies and related deliverables.

## What the site needs to make easy

Users should be able to:

- browse by project
- browse by deliverable
- click into a detailed deliverable page
- understand who owns each area
- see what problem each deliverable solves
- see what changes as a consequence of the work
- view the plan as a timeline / Gantt
- understand dependencies between deliverables
- see the three major cross-programme dependencies

## Design principle

The plan should not read as a static document. It should behave like a browsable delivery map.

A user should be able to move from the whole programme view to a specific deliverable, then back out to the timeline or dependency view.
